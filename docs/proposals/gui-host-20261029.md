# P5-U2 主机控制台与采集后台（2026-10-29）

## 结果与授权

按 owner 本轮要求（PLAN D17），UI 仅在主机提供；被采集机运行后台，接收主机命令并推送数据。完成代码和本机验证，尚未重新打包、发版或部署到实际双机。本轮覆盖第一轮 P5-U1 中的角色切换、双端 UI 和手动注册设计。

## 产品行为

- 主机默认以 `--role host` 启动，固定为接收端；被采集机以 `--role capture` 启动，其 `/`、`/ui`、`/ui/` 返回 404。自定义角色标签保留底层诊断兼容行为。
- 控制端口默认 **5143**。主机页面仅填写被采集机 IPv4，不填写 URL 或端口；旧 IPv4 URL 配置读取时迁移到 5143。显式 `--port` 只供隔离测试和诊断。
- 页面加载时枚举网卡，从下拉列表选择本机连接网口；增加 Windows 名称、状态、MAC 和 IPv4 元数据，保留旧 `/adapters` 字段。
- 采集参数在主机保存并下发，MTU 两端共用。被采集机不需要保存对端地址或网卡；启动采集时根据到主机的控制路由地址精确匹配网卡，匹配不唯一会报错。主机可取得所选网卡 MAC 时使用单播。
- 移除本机角色、共享内存名称、手动注册和对端控制台入口。产品配置固定 `Local\VirtualCaptureVcamFrame` 与自动注册。
- 按 owner 后续要求移除画面来源、像素转换、发送批大小和链路 MTU，连同来源相关的测试图案控件；连接配置仅显示 IP、网卡和目标帧率。保存时从后台已保存配置复制未显示参数，避免重置现有采集/传输设置，默认值与底层 API 保持不变。
- 总览使用同一个按钮切换“开始采集”与“停止采集”；回收尚未完成时保留停止入口。
- 新增 `scripts/start-capture-worker.ps1`，在当前登录用户会话隐藏启动后台，并检查既有监听以避免重复启动。DDA 需要登录桌面会话；主机及其下游软件须使用同一用户读取 HKCU 注册。

agent 仍为单文件、零运行时依赖。未改 raw L2 包头、原生采集/传输算法或验收判据；脚本不自动修改网卡 IP 和防火墙。

## 接收与虚拟卡生命周期

1. 开始前检查对端版本、`product_revision=2` 和 `product_role=capture`；旧版即使版本号相同也会被拒绝，要求更新后台。
2. 注册本目录虚拟采集卡，配置固定 FrameMap 并关闭 Motion 测试源；随后启动接收，再通知对端采集。
3. 停止时先通知对端停发，再停止本机接收并注销虚拟卡；对端失联也继续清理本机。
4. 部分注册失败、接收启动失败、对端启动失败均尝试回滚。接收进程异常退出由后台每秒检查并回收，不依赖浏览器轮询；正常退出和 OTA 替换前也执行清理。
5. 注销仅针对当前目录匹配的 DLL；失败保留 `vcam.managed`，允许继续重试。强制结束 agent 或断电不保证清理；注销不会强制释放下游已经持有的 COM 实例，下次采集可能需要重新选择设备。

产品模式缺少原生程序时直接报错。隔离预览和旧诊断模式的占位进程明确标记为测试桩，不显示伪造传输指标。
