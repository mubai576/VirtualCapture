# 控制台（P5 GUI，D16 方案 A）

浏览器打开任一台 agent：`http://<机器IP>:18080/ui`（本机 `http://127.0.0.1:18080/ui`）。两台机器的控制台功能相同。

## 首次配置（两台各做一次，在各自控制台"本机配置"里保存）
| 字段 | 采集机（当前 PC2 192.168.2.59） | 接收机（当前 PC1 192.168.2.100） |
|---|---|---|
| 角色 | 采集机（发） | 接收机（收） |
| 对端 agent | `http://192.168.2.100:18080` | `http://192.168.2.59:18080` |
| 本机网卡子串 | `Realtek` | `I226` |
| 其他 | 模式 dda、GPU 转换开、240 / 69、目标 MAC = 接收机 I226 MAC（`34:5A:60:4F:F2:33`） | 共享内存 `Local\VirtualCaptureVcamFrame`，自动注册 vcam：是 |

配置存在各自 ROOT 下 `vc-config.json`，可直接编辑（字段与校验见 skill references/agent-api.md）。

## 日常使用
1. 点 **开播**：收端先起（按需注册虚拟采集卡）→ 发端起 dda。下游软件打开 `VirtualCapture` 即有画面。
2. 看 **链路指标**：丢帧/哈希错应为 0；延迟曲线 = 发端段、重组、vcam 三段 p99（同机 QPC，不跨机比）。
3. 点 **停播**：先停发端再停收端。

## 排障
- "对端未连接"：对端 agent 未运行或 `对端 agent` 地址错。
- 开播报 `peer role ...`：两端角色不互补，改配置。
- "虚拟采集卡 未注册/路径不符"：点"注册虚拟采集卡"（HKCU，需与下游软件同一 Windows 用户）。
- 产品模式会话不限时（frames 0 / timeout 0），hashlog 每小时约 60MB/端，长期运行留意 run/ 空间。
- 预览画面仍用 `vc-monitor.exe`（读同一共享内存）。
